REGLAS DE TRANSFORMACIÓN OBLIGATORIAS:

1. Una fila de "CONSOLIDADO UAT" = un ticket.

2. `id` no se incluye (autoincremental).

3. `codigo`: prefijo "GAR_" + `Código Caso Prueba` + '-' + correlativo (3 dígitos). Ej: "GAR_SC_30.2-001". Máx. 20 caracteres. Tipo String(20).

4. `titulo`: `LEFT(CONCAT(Código Caso Prueba, ' - ', [RESUMEN] Caso de Prueba (Texto)), 200)`.

   IMPORTANTE — DEFINICIÓN DE [RESUMEN]:
   El [RESUMEN] NO es un truncado ni un recorte mecánico de caracteres. Es una SÍNTESIS SEMÁNTICA que se genera leyendo el texto COMPLETO de la columna "Caso de Prueba (Texto)" y produciendo una versión corta y coherente que capture la idea principal.

   Reglas del [RESUMEN] semántico:
   - Leer el contenido COMPLETO de "Caso de Prueba (Texto)".
   - Producir una síntesis coherente y legible de ~50 caracteres (máximo 60).
   - Frase comprensible por sí misma, no un corte arbitrario.
   - Mantener el sujeto/verbo principal.
   - Eliminar palabras vacías, redundancias y enumeraciones largas.
   - No incluir saltos de línea ni espacios múltiples.
   - No cortar palabras a la mitad.
   - Si "Caso de Prueba (Texto)" viene vacío → usar `Código HU`.
   - Si ambos vacíos → usar `Historia de Usuario`.
   - Tipo String(200).

   Ejemplos:
   - "Al completar los campos obligatorios y presionar el botón guardar, se calcula la Calificación Final por fórmula del mantenedor..." → "Validar cálculo de calificación al guardar"
   - "Realizar prueba conjunta Desarrollo y Negocio para confirmar control de exceciones por borrado de tabla..." → "Prueba conjunta de control de excepciones"
   - "Dentro de la pestaña Informes Validación, se visualiza el campo Nota Inicial..." → "Verificar visualización y cálculo de Nota Inicial"
   - "Si el servicio de correo no está disponible, el sistema registra el error en los logs..." → "Validar manejo de error y reintento de correo"
